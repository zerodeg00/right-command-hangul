# Right Command Hangul

macOS에서 오른쪽 `Command(⌘)` 키와 Windows 키보드의 오른쪽 `Alt` 키를
한/영 전환키로 바꿔 주는 작은 메뉴바 앱입니다.

MacBook 내장 키보드와 macOS 또는 Windows 모드로 연결된 외장 키보드에서
사용할 수 있습니다. Caps Lock과 왼쪽 `⌘`는 원래 기능을 그대로 유지합니다.

## 왜 만들었나요?

Windows 키보드에 익숙하다가 Mac을 사용하면 한/영 전환키의 위치가 불편하게
느껴질 때가 많습니다. macOS에서는 Caps Lock이나 `Control-Space`로 입력
소스를 전환할 수 있지만, Caps Lock을 본래 용도로 계속 사용하고 싶거나 키
조합이 아닌 오른손 엄지의 단일 키로 빠르게 전환하고 싶은 사람도 있습니다.

이 문제를 해결하는 대표적인 방법은 Karabiner-Elements입니다. 강력하고 좋은
도구지만, 단지 오른쪽 `⌘` 하나를 한/영키로 바꾸기 위해 시스템 입력을 다루는
큰 프로그램을 추가로 설치하고 권한을 부여하는 것은 부담스럽게 느껴졌습니다.

그래서 macOS에 이미 포함된 기능만 이용하는 작은 메뉴바 앱을 만들었습니다.
별도의 키보드 커스터마이징 앱이나 패키지 관리자를 설치하지 않고, Apple의
기본 API만으로 오른쪽 `⌘`를 한/영 전환키로 사용할 수 있습니다.

## 주요 특징

- Karabiner-Elements를 설치하지 않아도 됩니다.
- 메뉴바에서 키 매핑을 켜고 끄고, 전환 방식을 선택할 수 있습니다.
- 기존 앱 전환 방식과 선택 기능인 첫 글자 보호에서 접근성 권한을 요청합니다.
- 첫 글자 보호를 끈 macOS 기본 단축키 방식은 접근성 권한 없이 F18 매핑만 적용합니다.
- 입력 모니터링 권한은 요구하지 않습니다.
- Caps Lock 기능을 변경하지 않습니다.
- 왼쪽 `⌘`는 기존 Command 키로 계속 사용할 수 있습니다.
- MacBook 내장 키보드와 외장 키보드에 함께 적용됩니다.
- 로그인하면 자동으로 실행됩니다.
- 네트워크 통신, 업데이트 확인, 사용자 데이터 수집을 하지 않습니다.
- 소스 코드가 짧아 실제 동작을 직접 확인할 수 있습니다.

## 요구 사항

- macOS
- 시스템 설정에 한국어 입력 소스가 추가되어 있어야 합니다.
- 외장 키보드는 macOS 모드로 연결되어 있어야 합니다.
- Xcode Command Line Tools의 `clang`이 필요합니다.

한국어 입력 소스는 다음 경로에서 추가할 수 있습니다.

> 시스템 설정 → 키보드 → 텍스트 입력 → 편집 → `+` → 한국어

`clang`이 없다면 다음 명령으로 Command Line Tools 설치 창을 열 수 있습니다.

```sh
xcode-select --install
```

## 설치 방법

저장소를 내려받고 설치 스크립트를 실행합니다.

```sh
git clone https://github.com/zerodeg00/right-command-hangul.git
cd right-command-hangul
./scripts/install.sh
```

설치에는 `sudo`가 필요하지 않습니다. 설치 스크립트는 다음 작업을 수행합니다.

1. 현재 Mac에서 네이티브 실행 파일을 빌드합니다.
2. 앱을 `~/Applications/Right Command Hangul.app`에 설치합니다.
3. 로그인 시 자동 실행되도록 `~/Library/LaunchAgents`에 등록합니다.
4. 메뉴바 앱을 시작하고 저장된 매핑 설정과 전환 방식을 적용합니다.

설치가 끝나면 로그아웃하거나 재부팅할 필요 없이 바로 사용할 수 있습니다.
처음 설치하면 기존 앱 전환 방식으로 시작하며, 접근성 권한을 요청합니다.
권한을 허용하거나 메뉴에서 macOS 기본 단축키 방식을 선택해 주세요.

## 사용 방법

메뉴바의 **한/영**을 클릭합니다.

- **오른쪽 ⌘/Alt → F18 매핑 사용**: 매핑을 켜거나 끕니다. 끄면 오른쪽 키의
  원래 기능을 사용할 수 있습니다. 기존처럼 오른쪽 Command와 Alt/Option에 함께 적용됩니다.
- **macOS 기본 단축키로 전환**: 앱이 F18을 가로채지 않고 macOS에 전달합니다.
- **앱에서 직접 전환 (기존 방식)**: 앱이 F18을 받아 ABC와 두벌식 사이를 전환합니다.
- **첫 글자 보호 (실험, 접근성 필요)**: 기본 단축키 방식에서 전환 직후 입력을
  잠시 보관합니다. 기본값은 꺼짐이며 메뉴에서 바로 끌 수 있습니다.
- **키보드 단축키 설정 열기…**: macOS 키보드 설정을 엽니다.
- **접근성 설정 열기…**: 기존 방식과 첫 글자 보호에 필요한 권한 설정을 엽니다.
- **종료 (키 매핑 해제)**: 매핑을 해제하고 앱을 종료합니다. 다시 시작하려면
  응용 프로그램 폴더에서 앱을 엽니다.

켜짐 상태와 전환 방식은 다음 실행과 로그인 후에도 유지됩니다.
왼쪽 Command와 Caps Lock 기능은 변경하지 않습니다.

### macOS 기본 단축키 방식 설정 (권장)

1. 메뉴에서 **macOS 기본 단축키로 전환**을 선택하고 매핑을 켭니다.
2. **키보드 단축키 설정 열기…**를 클릭합니다.
3. 키보드 단축키 → 입력 소스에서 **이전 입력 소스 선택**을 활성화합니다.
4. 해당 단축키 편집란에서 오른쪽 Command 또는 Alt를 눌러 **F18**로 지정합니다.

이 방식에서는 **오른쪽 키 → F18 → macOS 입력 소스 전환**으로 처리합니다.
앱이 키를 가로채거나 전환 직후 입력을 보관·재전달하지 않습니다. 실제 일반 텍스트
입력란에서 전환 직후 첫 글자가 정상 입력되고, 기존 방식보다 전환이 더 부드럽다는
사용자 확인을 받았습니다. 속도를 정량 측정한 결과는 아니며 환경에 따라 차이가 있을 수 있습니다.

빠른 전환 직후 첫 글자가 이전 언어로 입력되는 현상이 보고되어, 선택 가능한
**첫 글자 보호**를 시험 중입니다. 보호 기능은 F18을 macOS에 그대로 전달하고,
입력 소스가 바뀐 것을 확인하는 즉시 보관한 키를 전달합니다. 별도의 고정 대기는
추가하지 않으며, 변경을 확인하지 못하면 약 0.25초 후 입력 해제를 시도합니다.
현재 Mac의 채팅 입력란에서 사용자가 빠르게 양방향 전환하며 시험했고,
첫 글자가 정상이며 끊김도 없다고 확인했습니다. 모든 앱·입력 조건에서의 검증은 아직 하지 않았습니다.

보호 기능에는 접근성 권한이 필요하며, 보안 입력 중에는 보호가 적용되지 않습니다.
앱이 입력란 정보를 제공하지 않으면 보호 없이 기본 F18 방식으로 동작합니다.
키를 보관한 사이 입력란이나 보안 입력 상태가 바뀌면 다른 입력란에 전달하지 않고
보관 중인 키를 취소하며 경고음과 메뉴 안내를 표시합니다. 이 경우 해당 키는 다시 입력해야 합니다.
보호 기능을 끄면 접근성 권한 없이 사용하던 F18 매핑 방식으로 돌아갑니다.
보안 입력(Secure Input) 활성 상태에서의 기본 단축키 동작은 아직 검증하지 않았습니다.
이 앱은 macOS 단축키 설정을 자동으로 변경하지 않으며, F18 지정은 처음 한 번
시스템 설정에서 직접 해야 합니다.

### 기존 앱 전환 방식

접근성 권한을 허용한 뒤 오른쪽 Command 또는 Alt를 누르면 입력 소스가 전환됩니다.
영문은 `ABC`, 한국어는 `두벌식`을 우선 사용하며, 없으면 활성화된 다른 영문 또는
한국어 입력 소스를 선택합니다. 업데이트 후 권한을 다시 허용해야 할 수 있습니다.

Chrome 등 다른 앱이 보안 입력(Secure Input)을 유지하면 기존 방식의 키 수신이
차단됩니다. 해당 앱에서 비밀번호 입력란을 벗어나거나, 내용을 저장하고 앱을 완전히
종료해 보세요. macOS 기본 단축키 방식으로 전환하는 것도 대안입니다.

## 제거 방법

저장소 폴더에서 다음 명령을 실행합니다.

```sh
./scripts/uninstall.sh
```

로그인 에이전트와 앱이 삭제되고 오른쪽 Command와 Alt의 F18 매핑도 해제됩니다.
제거 스크립트도 현재 소스를 빌드하므로 Xcode Command Line Tools가 필요합니다.
설치·제거 시에는 기존 매핑을 임시 보관해 구버전 앱이 종료되면서 다른 키 매핑을
지우는 경우에도 복원합니다. 실패하면 복구용 백업 경로를 출력합니다.

## 어떻게 동작하나요?

macOS의 일반 키 상태 API는 왼쪽과 오른쪽 Command 키를 동일하게 취급합니다.
이를 구분하기 위해 다음과 같이 동작합니다.

1. Apple의 IOKit API로 오른쪽 Command와 Right Alt의 HID 코드를 F18에 매핑합니다.
   다른 키의 매핑은 보존하며, 같은 키에 다른 매핑이 있으면 덮어쓰지 않고 실패를 표시합니다.
2. 기본 단축키 방식에서는 F18을 macOS에 그대로 전달합니다. 아래는 기존 앱 전환 방식의 동작입니다.
3. 백그라운드 서비스가 접근성 이벤트 탭에서 F18을 직접 받아 소비하고 Apple의
   Text Input Source API로 한국어와 영문 입력 소스를 전환합니다.
4. 전환 직후의 일반 키 입력은 macOS가 입력 소스 변경을 알릴 때까지 잠시 보관한
   뒤 원래 순서대로 전달합니다.
5. 변경 알림이 누락되더라도 0.25초 안에는 보관한 키를 전달해 입력이 사라지지
   않게 합니다.

기존 앱 전환 방식은 macOS 이벤트 큐에서 키 입력을 기다리고 F18을 소비하므로,
F18이 현재 앱까지 전달되어 경고음이 발생하는 것을 방지합니다. macOS의 입력 소스 단축키 설정을 수정하거나 실제 입력 문자를 읽지 않습니다.
F18은 일반 키보드에 거의 없는 키이므로 다른 키와 충돌할 가능성도 낮습니다.

## 보안과 개인정보

- 관리자 권한을 사용하지 않습니다.
- 접근성 권한은 기존 방식의 F18 처리와 전환 직후 키 이벤트의 임시 보관·재전달에 사용합니다.
  첫 글자 보호는 재전달할 입력란이 바뀌지 않았는지도 확인하며, 입력란의 문자 내용은 읽지 않습니다.
- 입력 모니터링 권한을 요청하지 않습니다.
- 키 입력 내용이나 작성 중인 문자를 기록하거나 저장하지 않습니다.
- 인터넷에 연결하지 않습니다.
- 사용자 응용 프로그램 폴더의 앱과 로그인 에이전트를 설치하고, 선택한 설정을 로컬에 저장합니다.

## 제한 사항

- 오른쪽 `⌘`는 한/영 전환 전용이 되므로 Command 조합키로 사용할 수 없습니다.
- macOS에서 Right Alt와 Right Option은 같은 HID 키이므로, 오른쪽 `Option`도
  한/영 전환 전용이 됩니다.
- macOS 로그인 화면에서는 동작하지 않습니다. 사용자 로그인 이후에만
  동작합니다.
- 다른 도구가 `UserKeyMapping` 전체를 다시 적용하면 이 앱의 매핑을 덮어쓸 수 있습니다.
- 외장 키보드가 Windows 모드라면 오른쪽 키가 다른 HID 코드로 전달될 수
  있습니다. 키보드를 macOS 모드로 전환해 주세요.
- 기존 앱 전환 방식은 접근성 권한이 필요하며, 보안 입력 활성 중에는 동작하지 않습니다.
- macOS 기본 단축키 방식은 F18 단축키를 처음 한 번 직접 지정해야 합니다. 앱을 제거해도
  이 시스템 단축키 설정은 남으므로 필요하면 직접 원복해 주세요.

## 문제 해결

### 오른쪽 Command 또는 Alt를 눌러도 전환되지 않아요

서비스가 실행 중인지 확인합니다.

```sh
launchctl print "gui/$(id -u)/com.github.right-command-hangul"
```

메뉴에서 매핑이 켜져 있는지 먼저 확인합니다. `state = running`이 보이지 않으면
`~/Applications/Right Command Hangul.app`을 열거나 설치 스크립트를 다시 실행합니다.

```sh
./scripts/install.sh
```

외장 키보드를 사용한다면 키보드가 macOS 모드인지도 확인해 주세요.

### 입력 소스 전환 기능만 확인하고 싶어요

아래 명령은 키를 누르지 않고 입력 소스를 한 번 전환합니다.

```sh
"$HOME/Applications/Right Command Hangul.app/Contents/MacOS/right-command-hangul" --toggle
```

현재 입력 소스의 시스템 ID를 확인할 수도 있습니다.

```sh
"$HOME/Applications/Right Command Hangul.app/Contents/MacOS/right-command-hangul" --current
```

### 로그는 어디에 있나요?

```text
~/Library/Logs/RightCommandHangul/right-command-hangul.log
```

## 개발

직접 빌드하려면 저장소 루트에서 다음 명령을 실행합니다.

```sh
make
```

빌드 결과는 `build/right-command-hangul`에 생성됩니다. 회귀 테스트는 다음 명령으로 실행합니다.

```sh
make test
```

테스트는 기존 키 이벤트 분류와 빠른 연속 전환 대상 결정, 방식 변경 시 눌림 상태 및
대기 타이머 정리, 다른 키 매핑 보존과 충돌 거부를 검사합니다.

실제 Mac에서는 메뉴의 매핑 켜기/끄기, 방식 선택, 설정 저장·복원, 종료 시 매핑 해제와
두 방식의 일반 텍스트 입력 전환을 확인했습니다. 재부팅 후 동작과 보안 입력 상태에서의
기본 단축키 전환은 별도로 검증하지 않았습니다.
